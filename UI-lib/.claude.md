# UI-lib 组件库约束

当用户描述的需求涉及以下任一场景时，**必须**先来 UI-lib 文件夹，参考已有组件和版式骨架来构建页面：

- 编写 HTML 页面
- 制作 PPT / 演示文稿 / Slide
- 编写报告文件（A4 报告、培训材料等）
- 任何需要 UI 布局、数据展示、可视化图表的网页
---

## 一、两种工作模式

### 模式 A：自由对话（无 config.json）

用户直接在对话中描述需求，没有预先配置的项目。适用于快速原型、单页需求。

按"用户意图理解 → 选骨架 → 选主题 → 选组件 → 组装"流程执行。

### 模式 B：项目驱动（有 config.json）★ 推荐

用户已在 `report-tool/index.html` 中创建项目并填写配置。你说"开始生成报告"或提到项目名时，Claude 自动发现并读取 config.json。

项目可能位于：
- `report-tool/projects/<项目名>/`（推荐路径，多数情况）
- 用户指定的任意目录（通过工具页面"新建项目"或"导入项目"）

**此模式下严格按 config.json 的配置执行，不需要再猜测版式/主题/组件。**

---

## 二、用户意图理解（模式 A 使用）

用户通常不会使用组件库的内部术语，而是用自然语言描述需求。你需要主动推断意图并给出建议。

### 从口语到配置的映射

| 用户可能这么说 | 推断为 |
|--------------|--------|
| "报告"、"A4"、"打印"、"PDF"、"方案书" | A4 横版骨架 + 商务蓝白主题 |
| "PPT"、"演示"、"slides"、"翻页"、"汇报" | PPT 翻页骨架 + RC 浅蓝主题 |
| "网页"、"页面"、"官网"、"落地页"、"产品介绍" | 自由滚动骨架 + 暗黑科技或商务蓝白 |
| "培训"、"教程"、"操作手册" | A4 横版骨架 + 参考 pe-training-a4-bluewhite 模板 |
| "数据分析"、"图表"、"指标"、"KPI" | 优先匹配 stat-card + bar-chart + data-table |
| "流程"、"步骤"、"方法" | 优先匹配 process-step + circle-number |
| "时间线"、"里程碑"、"历程"、"演进" | 优先匹配 timeline 或 timeline-chart |
| "团队"、"成员"、"角色" | 优先匹配 hero-card |

### 当用户描述模糊时（模式 A）

**不要直接开始生成。** 先列出推荐方案让用户确认，例如：

> 根据你的需求，我建议：
> - 版式：A4 横版（适合打印和 PDF 导出）
> - 主题：商务蓝白
> - 组件：数据卡片、数据表格、流程步骤
>
> 这样可以吗？或者你想调整哪些部分？

确认后再开始组装。每轮只确认一次，不要反复追问。

### 用户明确指定时

如果用户直接说了"用 A4 横版"、"暗黑主题"、"加个柱状图"，直接采用，不需要再次确认。

## 三、config.json 驱动流程（模式 B）

### 3.1 发现与读取

当用户说"开始生成报告"或提到项目名时：

1. **优先扫描** `report-tool/projects/` 下的子目录，匹配项目名称（模糊匹配，如"货币基金"匹配"货币基金分析报告"）
2. **若未找到**，询问用户提供项目文件夹的绝对路径
3. 用户也可在对话中直接给出路径（如"打开 /Users/xxx/我的项目/ 这个报告"）
4. 读取对应目录下的 `config.json`
5. 如果同时匹配到多个项目，列出让用户选择

### 3.2 大纲理解（chapterOutline 不为空且 chapters 为空时）

当 config.json 的 `chapterOutline` 字段非空，但 `chapters` 数组为空时，说明用户通过工具页面的「批量输入」粘贴了原始大纲。此时：

1. **AI 理解大纲**：读取 `chapterOutline` 内容，用自然语言理解能力识别章节结构
2. **列出章节结构**：向用户展示识别出的章节列表（序号 + 标题 + 推断的描述），格式如：
   ```
   根据大纲，我识别到以下 5 个章节：
   1. 封面与摘要 — 报告封面、审计摘要、风险评级
   2. 核心财务指标审计 — 资产负债率、流动比率等趋势分析
   3. ...
   确认无误？或需要调整？
   ```
3. **用户确认后写入**：用户确认后，将章节信息写入 config.json 的 `chapters` 数组，并更新 `chapterOutline` 为 null（标记已处理）
4. **继续正常流程**：之后按正常的分章生成流程执行

**关键规则**：
- 不要用正则解析，用 AI 的自然语言理解能力
- 支持任何格式：markdown 标题、纯文本分段、编号列表、口语化描述、对话记录混排等
- 识别后必须让用户确认，不要直接生成
- 如果用户的某个章节描述过于模糊，可以追问补充细节

### 3.3 分章生成（config.mode = "chapter"）

```
读取 config.json
  → 找到第一个 status = "pending" 的章节
    → 读 UI-lib manifest.json 了解组件路径
    → 读 layout 对应的骨架 HTML（skeletons/xxx-skeleton.html）
    → 读 theme 对应的主题 CSS（tokens/xxx.css）
    → 根据章节配置决定生成方式：
      ├─ customLayout 非空 → 优先按自定义描述生成，忽略 components 列表
      └─ customLayout 为空 → 按 components 列表逐个读取 meta.json + HTML
    → 如果有 dataFile，读取 data/ 下的数据文件
    → 根据 config.tags 调整报告语气和风格（如"高管汇报"→结论导向、精简有力；"培训材料"→循序渐进、图文并茂）
    → 根据章节 desc + 数据 + 组件/自定义描述 生成 chapter-XX-xxx.html
    → 生成的文件保存到项目目录下
    → 更新 config.json 中该章节 status 为 "draft"
    → 告知用户：第X章已生成，可预览，确认后说"继续"生成下一章
      ↓
用户对话修改当前章（改内容、调样式）
  → 用户说"继续" / "下一章" / "生成第X章"
    → 更新当前章 status 为 "done"
    → 找到下一个 pending 章节，重复上述流程
```

**关键规则：**
- 每轮只生成一章，不超过 800 行
- 生成前先读骨架和模板，理解组装方式
- 生成后务必更新 config.json 中的 status
- 用户说"继续"才进入下一章，不要自动连续生成

### 3.4 一次性生成（config.mode = "full"）

适用于 3-5 页短报告：

1. 读取 config.json → 遍历所有章节
2. 读取所有引用的组件和数据
3. 分批生成（每轮 ≤ 800 行）：
   - 第1轮：封面 + 前 2-3 章
   - 第2轮：后续章节
   - 第3轮：收尾 + 页码 + 打印控制
4. 单文件输出

### 3.5 组装（所有章节 done 后）

用户说"组装报告"或点击工具页面的组装按钮时：

1. 确定项目路径（优先 config.json 所在目录）
2. 检查所有章节 status 是否为 "done"
3. 如有未完成的章节，告知用户
4. 全部完成后，按 chapter order 合并：
   - 提取每个 chapter HTML 的 `<body>` 内容
   - 统一内联主题 CSS（从 token 文件读取并写入 `<style id="token-css">`）、页面编号、打印控制
   - 输出 `<项目路径>/output/<projectName>.html`（使用 config.json 中的 projectName 作为文件名）
5. 告知用户组装完成，文件位置

也可通过脚本：`node report-tool/assemble.cjs <项目文件夹绝对路径>`

### 3.6 自定义组件 vs 组件库

当章节的 `customLayout` 字段非空时：
- **优先按 customLayout 描述生成**，这是用户自己描述的展示需求
- components 列表可以为空，仅作参考
- 生成时仍然使用 layout 骨架和 theme 主题的 CSS 变量
- 如果 customLayout 和 components 同时存在，以 customLayout 为准

当 `customLayout` 为空或 null 时：
- 严格按 components 列表选取组件
- 先读每个组件的 meta.json，再读 HTML 源码
- 模仿 templates/ 中的组装方式嵌入骨架

### 3.7 数据文件处理

config.json 中 `dataFile` 指向 `data/` 下的文件。格式不限：

| 格式 | 处理方式 |
|------|---------|
| `.csv` | 直接读取，解析行列数据 |
| `.xlsx` | 读取原始内容；如需要结构化数据，用 Python 脚本转换 |
| `.docx` | 直接读取文本内容 |
| `.pdf` | 直接读取内容 |
| `.txt` / `.md` / `.json` | 直接读取 |

从数据文件中提取关键数字、日期、名称等，填充到组件中。

## 四、资源层级（由底层到上层）

```
tokens/        → 主题 CSS 变量（颜色、字体、间距）
components/    → 可复用的 Vue 组件（数据卡片、时间线、流程步骤等）
charts/        → 图表组件（柱状图、时间线图）
skeletons/     → 版式骨架（页面结构框架，含 @media print）
templates/     → 完整案例（骨架 + 组件 + 主题的组装成品）
```

## 六、组件读取方式

每个组件目录包含两个文件：
- `组件名.html` — 组件的完整 HTML 源码（含样式和逻辑）
- `组件名.meta.json` — 组件的元信息（props/slots/usage/promptHint）

**读取组件时，先读 meta.json 了解组件的参数和用法，再根据需要读 HTML 源码。** meta.json 的结构：

```json
{
  "name": "stat-card",
  "label": "数据卡片",
  "description": "组件功能简述",
  "props": { "参数名": { "type": "类型", "required": true/false, "desc": "说明" } },
  "slots": ["可替换的内容区域"],
  "echarts": false,
  "usage": "示例代码片段",
  "promptHint": "适用于xxx场景"
}
```

## 七、生成规则

1. **先读 manifest.json** — 每次开始生成前，先快速浏览 manifest.json 了解当前有哪些可用组件，避免遗漏或发明不存在的组件
2. **有 config.json 就按 config 走** — 不要自作主张改变用户已配置的版式/主题/组件/章节结构
3. **customLayout 优先** — 章节的 customLayout 非空时，以自定义描述为准生成，忽略 components 列表
4. **模糊需求先读模板** — 模式 A 且用户描述概括时，先完整读取匹配度最高的模板，理解组装模式，再改编
5. **替换内容，保留结构** — 复制组件 HTML 时，保留其 DOM 结构和 CSS 类名，只替换文本内容和数据；如需调整样式，通过 CSS 变量覆盖
6. **通过 meta.json 了解参数** — 每个组件的可变参数在 meta.json 中声明，先读 meta.json 再读 HTML，避免通读大段源码
7. **单文件输出，自包含** — 所有 CSS 和 JS 内联在 HTML 中。主题 CSS Token 必须内联到 `<style id="token-css">` 标签中（将 token CSS 文件内容完整复制到 style 标签内），确保生成的 HTML 文件自包含，可在任意环境独立打开，不依赖项目目录结构。CDN 依赖（Tailwind、Vue、ECharts）使用绝对 URL 除外
8. **自动引入依赖** — 如果使用了图表组件（echarts: true），需在页面中引入 `<script src="https://cdn.jsdelivr.net/npm/echarts@5/dist/echarts.min.js"></script>`
9. **首轮只给框架** — 模式 A 第一轮生成时，先输出页面结构框架（封面+各页标题+占位内容），用户确认结构后再逐步填充详细内容
10. **A4 页面内容不可溢出** — 当选用的版式为 A4 横版时，`.a4-page` 固定为 297mm×210mm 且 `overflow: hidden`，必须遵守以下布局约束：
   - **可用内容区**：扣除 padding（18mm 上下 / 22mm 左右），实际可用区域约 253mm × 174mm
   - **字号阶梯**：页面标题 28-36px（`text-3xl`），正文 14-15px（`text-sm`/`text-base`），辅助文字 11-13px（`text-xs`），数据大字 40-48px
   - **列数限制**：详情卡片 ≤ 3 列，迷你统计卡片 ≤ 4 列，正文+图表等双栏布局用 `grid-cols-2`
   - **表格行数**：单页数据表格不超过 12-15 行（含表头），超出需分页或精简
   - **图表高度**：ECharts 图表在 A4 单页内高度不超过 260-280px
   - **内容超页处理**：内容超过一页可容纳量时必须拆分为多个 `.a4-page` section，禁止在一个 section 内堆砌导致溢出被裁剪
   - **弹性布局优先**：使用 `flex flex-col` 或 grid 自适应分布内容，仅页码使用绝对定位（`absolute bottom-[10mm]`）
   - **间距紧凑**：卡片间距 `gap-4`（16px），区块间距 `mb-4`/`mb-5`，避免过大留白浪费空间
   - **封面例外**：封面页可使用 `flex flex-col justify-center` 垂直居中，无内容溢出风险

## 八、输出文件规范

1. **默认位置** — 模式 A 生成的 HTML 放在项目根目录；模式 B 生成的分章文件放在项目文件夹下（config.json 所在目录，通常为 `report-tool/projects/<项目名>/` 或用户指定路径）
2. **告知用户** — 开始生成前，告知用户文件将保存在哪里
3. **迭代修改** — 后续修改直接编辑同一个文件，不需要重复确认位置
4. **禁止** — 不要在 `UI-lib/` 内部创建或修改任何文件

---

## 九、技术栈约束

- CSS 框架：Tailwind CSS（CDN 引入）
- JS 框架：Vue 3（CDN 引入，使用 `Vue.createApp`）
- 主题系统：生成时将 token CSS 文件内容完整内联到 `<style id="token-css">` 标签中，禁止使用相对路径引用
- 所有组件和骨架均为**单文件 HTML**，自包含样式和逻辑
- 版式骨架使用 `@page { size: A4 landscape }` 控制打印尺寸；`.a4-page` 固定 297mm×210mm + `overflow: hidden`，内容不可溢出
- 所有颜色使用 CSS 变量：`color: var(--primary-500)`，`background: var(--surface)`
- @media print 中设置 `print-color-adjust: exact; -webkit-print-color-adjust: exact;` 保留打印颜色

---

## 禁止事项

- 不要从零手写 HTML/CSS 布局，优先复用骨架和组件
- 不要修改 UI-lib 内部的组件文件（除非用户明确要求维护组件库本身）
- 模式 B 下不要自作主张改变用户在 config.json 中的配置
- 修改组件前先确认 manifest.json 中的注册信息
- 每轮生成不超过 800 行
- 分章模式下每轮只生成一章，等用户确认后再继续
- 禁止在生成的 HTML 中使用相对路径引用 UI-lib 下的任何资源
- 生成的报告文件必须是自包含的最终交付物，脱离项目目录也能正常打开
