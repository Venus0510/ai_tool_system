| | report 工具提示词页 | 直接 Claude Code + CLAUDE.md |

| 灵活性 | 受限于预设的参数组合 | 自然语言描述，想怎么改怎么说 |

### 你已经做对的事情

- **UI-lib 的分层很清晰**：tokens → components → charts → skeletons → templates，资源层级明确
- **CLAUDE.md 的约束很具体**：禁止从零手写、强制复用组件、每轮不超过800行
- **manifest.json 注册机制**：组件可发现、可管理

### 可以继续优化的方向

1. **每个子文件夹都可以加 CLAUDE.md**，比如 `templates/` 下放一个，说明模板的使用场景和参数变量
2. **组件文件头部可以加结构化注释**，标注可配置的 slot/prop/css变量，Claude 替换时更精准
3. **`index.html` 作为组件展示页**保留即可，开发组件时用来预览，用户生成页面时不需要它

本质上你现在的方案就是：**组件库 = 乐高积木，CLAUDE.md = 说明书，用户需求 = "我要搭个城堡"**，完全不需要中间那个提示词组装页面了。

## 我的分析和补充

### 1. 这个方向是对的

分章节是解决"超长文件 Claude 处理困难"最务实的方案。每章独立 HTML 文件，单章几百行，修改时只读当前章节，效率高。

### 2. config.json 设计建议

不只是存配置，应该作为 **Claude 的明确任务指令**。建议结构：

```json
{
  "projectName": "货币基金分析报告",
  "layout": "a4-landscape",
  "theme": "business-bluewhite",
  "mode": "chapter",          
  "chapters": [
    {
      "id": "cover",
      "title": "封面",
      "desc": "报告封面，含标题、日期、团队",
      "components": ["hero-card"],
      "dataFile": null,
      "status": "pending"
    },
    {
      "id": "overview", 
      "title": "产品表现概览",
      "desc": "七日年化、万份收益、规模变化",
      "components": ["stat-card", "data-table"],
      "dataFile": "data/overview.json",
      "status": "pending"
    }
  ]
}
```

关键是 `desc` 和 `components` 字段——Claude 读到后就知道这章要写什么、用什么组件，不需要用户再口头描述。

### 3. 还需要考虑的几个点

**a) 工具页面的"返回 Claude"方式**

配置填好后，用户怎么回到 Claude 生成？两种方式：

- 工具页放一个"复制提示词"按钮，生成一段简洁指令让用户粘贴到 Claude
- 或者更简单——用户在 Claude 里直接说"读取 report-tool/projects/货币基金/config.json，开始生成第1章"，Claude 自动执行

我倾向于后者，保持零粘贴。工具页面只管配置，Claude 只管生成。

**b) CLAUDE.md 需要新增触发规则**

```markdown
- 如果用户提到"继续生成报告"、"开始第X章"或指定了某个报告项目，
  必须首先读取对应项目的 config.json，按配置执行
```

**c) 章节组装**

所有章节完成后需要一个组装步骤。两种方案：

- 写一个简单的 Node 脚本（`node assemble.js 项目名`）
- 或者让 Claude 做最后一轮组装（读取所有 chapter，合并输出）

组装脚本更可靠，避免 Claude 在合并时遗漏内容。但脚本需要处理：提取每个 chapter 的 `<body>` 内容、统一 page 编号、合并到一个 HTML。

**d) 数据文件格式**

建议用简单的 JSON，用户可以手动编辑，Claude 读取也直接：

```json
{
  "title": "产品表现概览",
  "metrics": [
    { "label": "七日年化收益率", "value": "2.15%", "trend": "up" },
    { "label": "万份收益", "value": "0.5892", "trend": "flat" }
  ],
  "tableData": { "columns": [...], "rows": [...] }
}
```

**e) "一次性生成"模式**

config 中 `mode: "full"` 的情况，适合短报告（3-5页）。Claude 一次性读取所有章节定义和组件，输出完整 HTML。但仍然受 800 行限制，可能需要分 2-3 轮。

### 4. 一个潜在问题

工具页面的复杂度控制——不要让它变成另一个"重型工具"。核心功能就三个：

- 新建项目（填基本配置 + 定义章节）
- 打开项目（查看进度，调整配置）
- 查看各章节状态（pending / draft / done）

不需要在线预览、不需要内嵌 Claude、不需要复杂的数据编辑器。

### 1. 这个方向是对的

分章节是解决"超长文件 Claude 处理困难"最务实的方案。每章独立 HTML 文件，单章几百行，修改时只读当前章节，效率高。

### 2. config.json 设计建议

不只是存配置，应该作为 **Claude 的明确任务指令**。建议结构：

```json
{
  "projectName": "货币基金分析报告",
  "layout": "a4-landscape",
  "theme": "business-bluewhite",
  "mode": "chapter",          
  "chapters": [
    {
      "id": "cover",
      "title": "封面",
      "desc": "报告封面，含标题、日期、团队",
      "components": ["hero-card"],
      "dataFile": null,
      "status": "pending"
    },
    {
      "id": "overview", 
      "title": "产品表现概览",
      "desc": "七日年化、万份收益、规模变化",
      "components": ["stat-card", "data-table"],
      "dataFile": "data/overview.json",
      "status": "pending"
    }
  ]
}
```

关键是 `desc` 和 `components` 字段——Claude 读到后就知道这章要写什么、用什么组件，不需要用户再口头描述。

### 3. 还需要考虑的几个点

**a) 工具页面的"返回 Claude"方式**

配置填好后，用户怎么回到 Claude 生成？两种方式：

- 工具页放一个"复制提示词"按钮，生成一段简洁指令让用户粘贴到 Claude
- 或者更简单——用户在 Claude 里直接说"读取 report-tool/projects/货币基金/config.json，开始生成第1章"，Claude 自动执行

我倾向于后者，保持零粘贴。工具页面只管配置，Claude 只管生成。

**b) CLAUDE.md 需要新增触发规则**

```markdown
- 如果用户提到"继续生成报告"、"开始第X章"或指定了某个报告项目，
  必须首先读取对应项目的 config.json，按配置执行
```

**c) 章节组装**

所有章节完成后需要一个组装步骤。两种方案：

- 写一个简单的 Node 脚本（`node assemble.js 项目名`）
- 或者让 Claude 做最后一轮组装（读取所有 chapter，合并输出）

组装脚本更可靠，避免 Claude 在合并时遗漏内容。但脚本需要处理：提取每个 chapter 的 `<body>` 内容、统一 page 编号、合并到一个 HTML。

**d) 数据文件格式**

建议用简单的 JSON，用户可以手动编辑，Claude 读取也直接：

```json
{
  "title": "产品表现概览",
  "metrics": [
    { "label": "七日年化收益率", "value": "2.15%", "trend": "up" },
    { "label": "万份收益", "value": "0.5892", "trend": "flat" }
  ],
  "tableData": { "columns": [...], "rows": [...] }
}
```

**e) "一次性生成"模式**

config 中 `mode: "full"` 的情况，适合短报告（3-5页）。Claude 一次性读取所有章节定义和组件，输出完整 HTML。但仍然受 800 行限制，可能需要分 2-3 轮。

### 4. 一个潜在问题

工具页面的复杂度控制——不要让它变成另一个"重型工具"。核心功能就三个：

- 新建项目（填基本配置 + 定义章节）
- 打开项目（查看进度，调整配置）
- 查看各章节状态（pending / draft / done）

不需要在线预览、不需要内嵌 Claude、不需要复杂的数据编辑器。

- 写一个简单的 Node 脚本（`node assemble.js 项目名`）

### 1. 这个方向是对的

分章节是解决"超长文件 Claude 处理困难"最务实的方案。每章独立 HTML 文件，单章几百行，修改时只读当前章节，效率高。

### 2. config.json 设计建议

不只是存配置，应该作为 **Claude 的明确任务指令**。建议结构：

```json
{
  "projectName": "货币基金分析报告",
  "layout": "a4-landscape",
  "theme": "business-bluewhite",
  "mode": "chapter",          
  "chapters": [
    {
      "id": "cover",
      "title": "封面",

    },

关键是 `desc` 和 `components` 字段——Claude 读到后就知道这章要写什么、用什么组件，不需要用户再口头描述。

### 3. 还需要考虑的几个点

**a) 工具页面的"返回 Claude"方式**

配置填好后，用户怎么回到 Claude 生成？两种方式：

- 工具页放一个"复制提示词"按钮，生成一段简洁指令让用户粘贴到 Claude
- 或者更简单——用户在 Claude 里直接说"读取 report-tool/projects/货币基金/config.json，开始生成第1章"，Claude 自动执行

我倾向于后者，保持零粘贴。工具页面只管配置，Claude 只管生成。

**b) CLAUDE.md 需要新增触发规则**

```markdown
- 如果用户提到"继续生成报告"、"开始第X章"或指定了某个报告项目，
  必须首先读取对应项目的 config.json，按配置执行
```

**c) 章节组装**

所有章节完成后需要一个组装步骤。两种方案：

- 写一个简单的 Node 脚本（`node assemble.js 项目名`）
- 或者让 Claude 做最后一轮组装（读取所有 chapter，合并输出）

组装脚本更可靠，避免 Claude 在合并时遗漏内容。但脚本需要处理：提取每个 chapter 的 `<body>` 内容、统一 page 编号、合并到一个 HTML。

**d) 数据文件格式**

建议用简单的 JSON，用户可以手动编辑，Claude 读取也直接：

```json
{
  "title": "产品表现概览",
  "metrics": [
    { "label": "七日年化收益率", "value": "2.15%", "trend": "up" },
    { "label": "万份收益", "value": "0.5892", "trend": "flat" }
  ],
  "tableData": { "columns": [...], "rows": [...] }
}
```

**e) "一次性生成"模式**

config 中 `mode: "full"` 的情况，适合短报告（3-5页）。Claude 一次性读取所有章节定义和组件，输出完整 HTML。但仍然受 800 行限制，可能需要分 2-3 轮。

### 4. 一个潜在问题

工具页面的复杂度控制——不要让它变成另一个"重型工具"。核心功能就三个：

- 新建项目（填基本配置 + 定义章节）
- 打开项目（查看进度，调整配置）
- 查看各章节状态（pending / draft / done）

不需要在线预览、不需要内嵌 Claude、不需要复杂的数据编辑器。

### 3. 还需要考虑的几个点

**a) 工具页面的"返回 Claude"方式**

```

**c) 章节组装**

所有章节完成后需要一个组装步骤。两种方案：

- 写一个简单的 Node 脚本（`node assemble.js 项目名`）
- 或者让 Claude 做最后一轮组装（读取所有 chapter，合并输出）

**d) 数据文件格式**

```json

**e) "一次性生成"模式**

config 中 `mode: "full"` 的情况，适合短报告（3-5页）。Claude 一次性读取所有章节定义和组件，输出完整 HTML。但仍然受 800 行限制，可能需要分 2-3 轮。

### 4. 一个潜在问题

工具页面的复杂度控制——不要让它变成另一个"重型工具"。核心功能就三个：

- 新建项目（填基本配置 + 定义章节）
