## 组件库触发规则

当用户描述的需求涉及编写 HTML 页面、PPT 演示、A4 报告文件、UI 布局或数据展示页面时，**必须首先**读取并遵循 `UI-lib/.claude.md` 的约束，从 UI-lib 组件库中选取骨架、主题和组件来构建，禁止从零手写。

## 报告项目触发规则

系统支持两种工作模式，详见 `UI-lib/.claude.md`：

### 模式 A：自由对话（无 config.json）

用户直接在对话中描述需求，没有预先配置的项目。适用于快速原型、单页需求。

当用户说"开始生成报告"或描述报告需求，但 `report-tool/projects/` 下无匹配项目且用户未给出路径时，自动进入模式 A，按 `UI-lib/.claude.md` 中"用户意图理解 → 选骨架 → 选主题 → 选组件 → 组装"流程执行。

### 模式 B：项目驱动（有 config.json）

当用户提到以下情况时，说明已有项目上下文，**必须首先**查找并读取对应项目的 `config.json`：

- "继续生成" / "生成下一章" / "生成第X章"
- 指定了某个报告项目名称（如"货币基金分析报告"）
- "组装报告" / "合并章节" / "输出完整报告"

**查找 config.json 的方式（按优先级）**：
1. 优先扫描 `report-tool/projects/` 下的子目录，匹配项目名称（推荐路径，多数项目在此）
2. 若 projects/ 下有多个项目，列出项目让用户选择
3. 若只有一个项目，直接使用该项目，无需追问
4. 若未找到，询问用户提供项目文件夹的绝对路径
5. 用户也可直接给出路径（如"打开 /Users/xxx/我的项目/config.json"）

读取后严格按 `UI-lib/.claude.md` 中的分章生成流程执行。

## 对用户的基本承诺

- 用户不需要知道组件库的内部路径或组件名称，用自然语言描述需求即可
- 用户不需要知道 config.json 的格式，通过 report-tool/index.html 可视化配置
- 你负责理解意图、匹配组件、主动建议、按配置执行
- 生成的报告 HTML 文件必须是自包含的最终交付物：主题 CSS token 必须内联到 `<style>` 标签中，禁止使用相对路径（如 `../../UI-lib/`）引用组件库资源。CDN 绝对 URL 引用（Tailwind、Vue、ECharts）除外
- A4 横版骨架的 `.a4-page` 固定 297mm×210mm + `overflow: hidden`，生成内容必须适配可视区域、不可溢出，超出时拆分为多个 page section
